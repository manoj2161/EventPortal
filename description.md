# College Event Registration Portal

Data design (cleaned-up version)

## 1. Users

Students, teachers and admins share one list of users.

### At signup
- fullName, email, password
- category (student or organiser)

### System fields
- **emailVerified:** false at signup, true after verification
- verification token and its expiry time
- **isAdmin:** false by default; only the database controller changes it, finding the user by email

### Profile (filled after login)
- **Students:** phone, department, course, semester, rollNumber
- **Teachers:** phone, department, teacherID

### Login
- email and password, allowed only when emailVerified is true

## 2. Events

- id (unique, generated by the database)
- name, description, date, time, location, seats, registration deadline
- allowed department (one selected department, or all departments)
- createdBy (a reference to the user who created it)
- approval status (waiting or approved): teacher-created events start as waiting, admin-created events start as approved

## 3. Registrations (students only)

- event id
- student (a reference to the user)

### Rules
- The student's profile must be complete first.
- The student's department must match the event's allowed department, or the event must be open to all.
- A student can register for an event only once.
- Seats left = seats minus the number of registrations.
- Students only see events for their own department or for all departments.
- Students only see approved events, not events waiting for admin approval.
- Students see only approved events.
